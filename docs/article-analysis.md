# 参考文章分析

## 文档边界

super-agent-article-fulltext.md 是本项目的设计参考文章（该文为 DeepSeek 产品部于 2026-10-31 发布的第三方文章，全文不随本仓库分发，仅在本地保留作参考；本文档是本项目自己的整理与分析）；用户提供的规划文本是本次任务的执行要求。文章不等于代码规格，下面明确区分三类结论：

- 文章明确事实：文章直接描述的架构、机制、实验结果或开放问题。
- 工程推断：为了把文章落成开源项目而补充的实现设计。
- 待验证问题：文章没有给出答案、需要原型或运行数据验证的内容。

## 目标与场景

文章将 Super-agent 定义为跨 Session 的连续实体，目标是同时支持连续、高效、主动、持久四个特征。典型场景包括：跨 IM 和 GitHub 持续推进开发任务、观察群聊和 CI 事件、主动复现问题和提交 Pull Request，以及接入日程、邮件和文档的个人助手。

| 特征 | 文章含义 | 项目验证指标（工程推断） |
| --- | --- | --- |
| 连续 | 用户不必管理 Session，跨渠道保留关联 | 同一 Thread 或任务跨渠道可追踪；路由决策不丢失 |
| 高效 | 多个复杂任务并行，前台交互不被后台工具阻塞 | 新事件可在当前推理步结束后进入队列；任务吞吐和 p95 延迟可测 |
| 主动 | Agent 观察环境事件并在合适时行动 | 事件过滤准确率、误触发率、静默策略命中率 |
| 持久 | 跨设备在线，异常后自动恢复 | 任务恢复率、Watchdog 修复率、状态持久化完整性 |

## 核心机制还原

### 双层架构

文章事实：Router 层是常驻的全局路由和交互层，维护跨任务信息、分派任务、统一对外回复，不直接执行具体工作；Worker 层上下文隔离、并发执行具体任务，向 Router 汇报状态。Router 可以通过积压事件批处理降低单个决定成本；规模变大后可在 Router 内部过滤或分片。

输入和输出：Router 接收用户消息和环境 Trigger，输出路由决定、Worker 创建/更新/停止命令和对外回复；Worker 接收任务上下文及订阅 Thread 的事件，输出状态、结果、请求和错误。

工程推断：实现为 RouterService、WorkerRuntime、TaskScheduler 和持久化状态机，而不是把一个超长 LLM Session 当作唯一真相。Router 的 LLM 只负责语义判断，确定性路由和状态转换由程序完成。

难点：全局连续性与吞吐量存在权衡；Router 不能成为所有事件的同步瓶颈；Worker 共享环境时会出现冲突。

### 事件驱动与两级过滤

文章事实：群聊、邮件、日程、代码评审、CI 等输入统一称为 Trigger。程序层 Fast Path 先按来源、范围、白名单等规则过滤；候选事件再交给 LLM Slow Path 做语义判断。

工程推断：所有入口先规范化为版本化 Trigger；先做鉴权、去重、大小限制和确定性策略，再决定是否消耗模型调用。过滤结果、理由和策略版本必须持久化，便于审计和回放。

待验证：不同渠道的噪音比例、规则与模型过滤的成本边界、批处理大小的上下文上限。

### Thread 订阅与直通

文章事实：同一 IM 话题、GitHub PR 或邮件串组成 Thread。初始事件经过 Router 创建 Worker 并建立订阅；后续事件由程序直接发给订阅 Worker，Router 仍可观察全局状态。Thread 与 Worker 是多对多关系。

工程推断：采用带有效期和状态的 Subscription 实体；订阅匹配在程序中完成，Worker 可请求续订、取消或交回 Router。投递采用至少一次语义，Worker 以 event_id 幂等。

### Inline/Spill 与链式召回

文章事实：上下文窗口可视为 Cache。近期高概率使用的信息 Inline；低频或超限内容 Spill，只在窗口内保留引用和摘要；对象通过 ID 构成引用图，模型可以沿关联对象逐跳召回。

工程推断：上下文服务提供预算、摘要、引用图和工具读取接口；任何 Trigger、Thread、Task、Worker 和 Artifact 都有稳定 ID。上下文构建器必须记录注入对象和 token 预算，支持离线评估。

### 投机执行

文章事实：Agent 可根据信号后台提前复现问题、查找资料或准备草稿；结果有价值才交付，否则保持安静。

工程推断：增加 speculative 任务类型、成本上限、过期时间和交付门槛；投机结果默认不可直接产生外部副作用，必须经过审批或转为普通任务。

### 异步 ReAct Loop

文章事实：耗时工具改为 start()/stop()；启动后立即返回 Started，后台完成后再以事件注入结果，模型可主动终止长任务。

工程推断：执行器以 Run 和 ToolCall 状态机实现，状态包括 PENDING、RUNNING、SUCCEEDED、FAILED、CANCEL_REQUESTED、CANCELLED、TIMED_OUT；所有状态转换可恢复且有超时、重试和审计记录。

### 多信道交互

文章事实：IM 需要低打扰、短回复；GitHub、邮件和文档适合结构化、高信息密度的异步交付。Worker 内部细节不直接输出到外部信道。

工程推断：ChannelAdapter 只负责收发和格式能力；DeliveryPolicy 根据渠道、事件类型和风险等级决定摘要、审批和发送方式。

### 计算、状态和环境分离

文章事实：云端无状态 Agent Loop 与持久化 Session 状态分离；执行环境留在原地，通过轻量 daemon 接入，支持 BYOM、云主机和间歇在线设备。

工程推断：云端只保存任务状态、引用、策略和审计；端侧 daemon 使用短期凭据和能力白名单执行命令。云端模型不直接获得机器密钥，敏感操作由端侧代理代办。

### Watchdog

文章事实：独立 Watchdog Session 由定时消息驱动，既检查基础设施也检查 Worker 是否有实质进展、是否偏离目标，并可介入修复。

工程推断：Watchdog 使用独立租约和权限边界，读取健康快照、进展信号和错误分类；自动修复动作必须幂等、可回滚并留下审计记录。

## 文章实验的可复用结论

文章的合成实验对比了 Super-agent、去掉直通的 Super-agent、单 Session 加 Subagent。结论是双层架构在多任务消息流中完成时间更短且更稳定；直通机制显著减少 Router 的决策和缓存 token；Router 在事件拥堵时通过批处理降低单个决定的分摊推理时间。

这些结果只能作为方向性证据，不能直接当作本项目性能承诺。后续应建立可重复的事件回放基准，至少测量端到端完成时间、Router 队列延迟、Worker 并发数、模型 token、误触发率和恢复时间。

## 局限、替代方案与选择

| 议题 | 文章方案 | 替代方案 | 本项目选择及理由 |
| --- | --- | --- | --- |
| 事件总线 | 逻辑上批处理和直通，未规定基础设施 | 直接 HTTP、Redis Streams、NATS、Kafka | MVP 用数据库 Outbox 加可替换 EventBus，避免过早引入运维复杂度；规模阶段评估 NATS/Redis Streams |
| Router 实现 | 单常驻 LLM Session | 规则引擎、多个 Router 分片、工作流编排器 | 先用确定性路由加单 Router Worker；把 LLM 判断限制在必要的语义决策 |
| 状态存储 | 持久 Session，未给模式 | PostgreSQL、事件溯源、文档库 | 以 PostgreSQL 作为事实源，关键状态用版本化状态机；暂不做全量事件溯源 |
| 执行环境 | 端侧 daemon，信任关系待解决 | 云沙箱、远程执行服务、用户自托管 | 先做受限本地执行器和显式能力授权，再增加 BYOM daemon；云端沙箱作为后续适配器 |
| 上下文检索 | 引用图链式召回 | 向量检索、全文检索、知识图谱 | 先做 ID 引用、摘要和全文索引；向量检索只在评估证明收益后加入 |
| 多 Agent 协作 | Worker 间少通信，靠共享 Thread 观察 | A2A、集中式黑板、工作流 DAG | MVP 只做 Router 到 Worker 的协作；跨实例 A2A 延后并单独设权限边界 |
| Watchdog | 独立 Agent Session | 纯监控规则、工作流补偿、人工值守 | 先用规则健康检查和可解释修复，再引入模型判断进展，避免失控 |

## 未解决问题

- Router 何时需要水平切分，分片键应是租户、项目、Thread 还是权限边界。
- 长期记忆的保留、删除、用户可见性和跨租户隔离策略。
- 端侧 daemon 在云端被入侵或提示词注入时的最小权限与凭据代理方案。
- 多 Worker 同时修改同一代码环境时的锁、分支、工作树和冲突恢复模型。
- 用户如何在不暴露底层 Session 的情况下查看任务、接管执行和批准高风险动作。
- 供应商模型差异、成本预算、上下文窗口和工具调用格式的兼容性。

## 结论

文章最重要的可迁移思想不是某个具体模型或渠道，而是把 Agent 变成事件驱动的持久化分布式系统：用 Router 维持全局连续性，用 Worker 提供隔离并发，用订阅直通减少协调开销，用异步执行解耦交互和工作，用存算分离与 Watchdog 支撑长期运行。本项目按这一核心保持方向，同时用确定性状态机、安全边界和可观测性补齐文章未展开的工程部分。
