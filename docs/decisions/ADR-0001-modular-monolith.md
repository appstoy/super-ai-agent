# ADR-0001：MVP 采用模块化单体

- 状态：Accepted
- 日期：2026-11-07

## 背景

Super-agent 需要事件、Router、Worker、调度和状态持久化，但项目当前没有真实负载或贡献者规模数据。直接拆成多个微服务会放大部署、调试和一致性成本。

## 候选方案

1. 模块化单体：一个部署单元，内部严格分层和接口隔离。
2. 从第一天拆成 API、Router、Worker、Bus、Watchdog 多服务。
3. 无明确边界的脚本集合。

## 决策

选择模块化单体。所有模块通过领域接口和版本化事件交互；当并发、故障隔离或团队边界达到阈值时，再按接口拆分进程。

## 代价与影响

- 早期部署和本地调试简单，能快速验证完整路径。
- 单进程故障隔离和独立扩缩容较弱，必须先实现租约、持久化 Run 和清晰模块边界。
- 未来拆分需要维护事件契约和跨进程幂等，不能依赖进程内共享对象。
