# 开发路线

路线按可交付能力排列。每阶段结束都必须有可运行产物、自动化验证和文档状态更新；除非前置阶段验收通过，不进入下一阶段。

## Phase 0：工程基线与安全地基

- **目标**：建立可重复开发、测试和发布的骨架。
- **范围**：Python 包结构、配置、日志、错误模型、数据库迁移、Docker Compose、CI、基础密钥管理、贡献指南草案。
- **前置**：无。
- **交付物**：可启动 API/CLI 空壳、健康检查、数据库连接、示例配置和 CI。
- **验收**：新机器按 README 可启动；单元测试、类型检查和 lint 在 CI 通过；日志不泄露测试密钥。
- **真实场景**：贡献者能在本地运行服务并执行一条健康检查。
- **风险**：过早锁定部署方式；保持模块化单体和接口抽象。

## Phase 1：持久化事件与最小 Agent

- **目标**：完成单用户、单环境、CLI/HTTP 输入到模型响应的闭环。
- **范围**：Trigger、Thread、Task、Run、State Store、ModelGateway、基础 Router、最小 Tool Registry（Mock/只读工具）、CLI 查询。
- **前置**：Phase 0。
- **交付物**：提交任务、持久化状态、调用一个模型供应商、重启后恢复可查询。
- **验收**：MVP 场景 1、4 和 6 通过；Mock 模型下测试可完全离线运行。
- **真实场景**：开发者可以通过 CLI 提交“分析这个仓库”的任务，由 Mock/只读工具读取受控输入并收到结果。
- **风险**：把模型输出当作状态真相；状态转换必须由领域代码控制。

## Phase 2：Router/Worker 并发与异步工具

- **目标**：验证文章最核心的双层架构和全双工执行。
- **范围**：Worker 隔离上下文、Subscription 直通、EventBus、异步 Tool start/stop、租约、超时、取消、重试、并发限制。
- **前置**：Phase 1。
- **交付物**：多个任务同时运行；同一 Thread 后续事件直达 Worker；运行中可接收新事件。
- **验收**：MVP 场景 2、3；重复事件不重复执行；故障注入后可恢复或明确失败。
- **真实场景**：一个任务运行测试时，用户可以立即提交第二个独立任务。
- **风险**：竞态和重复副作用；所有消费和工具完成都必须幂等。

## Phase 3：上下文、记忆与渠道输出

- **目标**：降低上下文浪费，提供可追踪的跨事件记忆和渠道适配。
- **范围**：Inline/Spill、摘要、引用图、链式召回、Delivery Policy、第二个渠道适配器、回放工具。
- **前置**：Phase 2。
- **交付物**：Context manifest、按预算构建提示词、渠道格式化和历史任务召回。
- **验收**：上下文不超过预算；召回链可审计；同一任务可跨 CLI 与 webhook 继续；回放结果稳定。
- **真实场景**：用户在 webhook 中补充约束，Worker 使用已有 Thread 上下文继续工作。
- **风险**：摘要丢失关键事实；保留原文引用和可按需读取能力。

## Phase 4：工具安全、端侧执行与主动策略

- **目标**：让 Agent 能在真实开发环境中安全执行，并开始主动响应。
- **范围**：Tool Policy、资源配额、受限 Shell/文件工具、审计、规则过滤、端侧 daemon、BYOM 注册、投机任务实验。
- **前置**：Phase 3；端侧 daemon 先在同一机器验证。
- **交付物**：能力声明、最小权限执行、签名命令、设备在线状态、Fast Path 过滤。
- **验收**：高风险操作默认拒绝；路径穿越、命令注入、超时和断线测试通过；端侧密钥不进入模型上下文。
- **真实场景**：Agent 在开发机的允许目录运行测试并返回报告。
- **风险**：云端提示词注入导致端侧越权；采用短期凭据、能力白名单和人工审批。

## Phase 5：Watchdog、可靠性与性能

- **目标**：支持长期运行、异常自愈和可量化性能。
- **范围**：规则 Watchdog、进展信号、停滞检测、恢复策略、事件回放基准、Router 批处理、OpenTelemetry、成本预算和告警。
- **前置**：Phase 4。
- **交付物**：健康快照、恢复报告、性能基线、故障演练和 SLO 草案。
- **验收**：进程崩溃、数据库短暂不可用、Worker 停滞、重复事件和模型超时均有预期恢复行为；核心指标可查询。
- **真实场景**：服务重启后未完成任务自动续跑，异常任务被标记并通知用户。
- **风险**：自动修复产生二次破坏；先规则后模型，修复动作幂等且可回滚。

## Phase 6：多信道开源产品与生态

- **目标**：形成可供普通用户和贡献者使用的开源项目。
- **范围**：GitHub/IM/邮件适配器、Web UI、插件 SDK、更多模型、Docker 部署、文档、License、SECURITY、CHANGELOG、Issue/PR 模板、版本发布。
- **前置**：Phase 5；每个外部渠道都通过安全评审。
- **交付物**：公开稳定 API、快速开始、示例部署、兼容性矩阵和首个可复现发行版。
- **验收**：新用户按文档完成安装和首个任务；适配器故障不影响核心任务；插件可独立测试。
- **真实场景**：团队把 Agent 接入 GitHub PR 和群聊，持续处理反馈并由用户验收交付。
- **风险**：生态扩张导致核心接口不稳定；采用版本化契约和兼容性政策。

## 阶段闸门

每阶段必须检查：功能验收、失败路径、权限边界、可观测性、文档链接、迁移脚本和回滚方式。任何阶段不应以“模型看起来能工作”作为唯一完成条件。
