# 安全与可靠性设计

## 威胁边界

系统把所有外部事件、渠道正文、仓库内容、邮件、工具输出和模型生成内容视为不可信数据。核心威胁包括提示词注入、凭据泄露、路径穿越、任意命令执行、重放事件、无限循环、资源耗尽、跨租户读取和 Worker 之间的状态竞争。

## MVP 必须具备

- 身份与租户：每个 Trigger、Task、Run、ToolCall 和 Delivery 绑定身份与权限边界；Webhook 验签；默认单用户也保留租户字段。
- 默认拒绝：工具必须声明能力、路径、网络、凭据、资源和副作用；未知能力、高风险操作和越界路径均拒绝。
- 密钥隔离：密钥只进入受控执行代理或环境变量注入点，不进入模型上下文、事件正文和普通日志。
- 资源限制：每个 Run 有超时、并发、输出大小、模型 token 和成本预算；超过预算暂停、失败或请求批准。
- 幂等与重放防护：外部事件使用签名和 dedupe_key；工具完成、Delivery 和恢复动作使用幂等键。
- 审计：记录授权、拒绝、审批、工具启动/停止、状态转换和恢复动作；Agent 不能删除审计记录。
- 人工控制：高风险外部副作用默认需要批准；用户可以停止、暂停和接管任务。
- 提示词注入隔离：系统指令、策略、事件正文、工具结果分层传递；模型文本不能直接改变程序权限。

## 后续增强

- 端侧 daemon 使用短期签名、设备撤销、能力租约和结构化参数。
- 云端执行环境使用沙箱、网络出口策略、文件系统隔离和供应链扫描。
- 对长期记忆提供可见、删除、导出和保留期限控制。
- 对模型和工具执行加入异常行为评分、人工抽样和红队回归集。
- 对跨实例 A2A 使用独立身份、最小权限和可验证消息格式。

## 可靠性控制

- 状态以持久化状态机为准，模型输出只能生成候选领域命令。
- Run 使用租约、心跳和恢复策略；错误分类决定重试、等待、暂停或失败。
- Watchdog 先采用规则检查停滞、重复失败和租约丢失；模型辅助判断必须受权限和预算限制。
- 自动修复必须幂等、有最大次数、可回滚，并通知用户关键变化。

## 验证要求

每个新增工具、渠道和执行环境都必须增加安全测试：路径和命令注入、凭据脱敏、重放、超时、断线、权限撤销和并发竞争。发布前运行安全回归集和依赖漏洞扫描，并在变更影响权限边界时新增 ADR。
