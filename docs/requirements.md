# 需求与优先级

## 范围说明

本文件定义可交付产品需求，不重复文章研究过程。MVP 以“一个用户、一个部署、一个受限执行环境、两个输入方式（CLI 与 HTTP webhook）”为边界，先验证持久化事件、Router/Worker 分工和异步任务闭环。

## 用户与场景

| 角色 | 主要目标 | MVP 入口 | 后续入口 |
| --- | --- | --- | --- |
| 个人开发者 | 给 Agent 下达开发任务并查看进度 | CLI、HTTP webhook | GitHub、IM、Web |
| 团队成员 | 让 Agent 观察 Thread 并持续推进任务 | 模拟事件适配器 | GitHub、Slack/飞书等 |
| 运维/维护者 | 查看失败、恢复任务和成本 | CLI 状态命令、结构化日志 | Web 控制台、告警 |
| 插件开发者 | 添加模型、工具、渠道和策略 | Python 接口 | 独立插件包、注册中心 |

| 能力 | MVP | 后续阶段 | 优先级 |
| --- | --- | --- | --- |
| 规范化 Trigger、去重、持久化 | 必须 | 增加更多来源 | P0 |

## 非功能需求

- **可靠性**：事件至少一次投递；重复事件不会创建重复任务；进程重启后可恢复未完成 Run。
- **可观测性**：每个请求、Trigger、Task、Run、ToolCall 和 Delivery 都有可关联 ID；日志不得包含密钥和完整敏感内容。
- **安全性**：默认最小权限；危险工具需要策略或人工批准；每个 Run 有超时、并发和成本预算。
- **可测试性**：核心领域逻辑可脱离 LLM 和数据库测试；事件回放可复现路由结果。
- **可移植性**：开发环境支持 Windows、macOS、Linux；生产部署提供 Docker Compose，避免依赖单一云厂商。
- **可扩展性**：模型、渠道、工具、存储和消息总线均通过接口注入，新增适配器不修改领域状态机。

## MVP 验收场景

1. 用户通过 CLI 提交任务；Router 创建 Task 和 Worker；Worker 使用 Mock 或只读工具契约并返回结果；用户可查询状态。
2. 同一 Thread 的第二个事件绕过 Router 直达已订阅 Worker，重复投递不会重复执行。
3. 后台工具运行时，CLI/API 可接收新的用户事件；新事件进入队列而不阻塞旧 Run。
4. 进程在工具运行中重启；恢复后 Run 进入可解释状态并完成重试或标记失败。
5. 未授权的文件路径、危险 Shell 命令和超预算调用被拒绝并写入审计记录。
6. 事件回放能够得到相同的过滤、订阅和状态转换结果，模型调用可用 Mock 替代。

## 明确不做

MVP 不做多租户商业 SaaS、完整 Web 控制台、任意远程代码执行、全量事件溯源、向量数据库强依赖、跨实例 A2A、自动发送高风险外部消息和无限制自主循环。
