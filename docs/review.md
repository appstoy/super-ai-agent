# 规划技术审查

审查视角：独立技术负责人，检查文章覆盖、职责边界、接口自洽性、MVP 范围、任务可执行性、安全、扩展性和跨会话接力。

## 通过项

- 文章的双层架构、事件驱动、订阅直通、Inline/Spill、异步 ReAct、存算分离和 Watchdog 均已映射到需求、架构或路线图。
- Router 不执行具体工具、Worker 不直接对外发送、状态由程序状态机控制，避免职责冲突和模型输出篡改事实。
- MVP 选择模块化单体、PostgreSQL Outbox 和一个受限执行环境，减少了早期运维和分布式一致性复杂度。
- 任务按阶段拆分，每项包含目标、依赖、文件、接口、测试和验收；阶段集成任务覆盖真实用户路径。
- 安全、审计、幂等、资源预算、恢复和可观测性从 Phase 0/1 纳入，而不是推迟到发布前。
- Agent.md 保持短小稳定；专项文档承担分析、架构、路线、任务、安全和开源规范；AGENTS.md 与 CLAUDE.md 只做兼容入口。

## 已修订的问题

- 补充了 Skills/Plugins 的职责和安全边界，避免未来扩展通过提示词绕过工具策略。
- 增加独立安全文档，明确 MVP 必须措施、后续增强和验证要求。
- 增加开源工程文档，覆盖许可证、CI、Docker、贡献者和发布门槛。
- 增加 Phase 0 至 Phase 6 的任务文件和阶段验收，避免只有概念没有执行单元。
- 修订 MVP 工具范围，避免需求矩阵与路线图对真实 Shell 执行时点不一致。

## 保留的待验证项

- Router 单实例吞吐、批处理上限、分片阈值和上下文长期增长。
- 端侧 daemon 的实际威胁模型、凭据代理和多设备冲突处理。
- 不同模型供应商对结构化工具调用、成本和上下文召回的差异。
- Thread/Task 的用户界面形态、人工中途接管和跨实例 A2A。

## 审查结论

规划达到“可以交给未参与初始讨论的 AI 编程 Agent 接力执行”的门槛。下一次工作应从 P0-T001 开始；在该任务完成前不应实现 Router、Worker 或渠道功能。任何改变本结论的重大设计变化都必须新增 ADR 并更新 roadmap、tasks 和 progress。
