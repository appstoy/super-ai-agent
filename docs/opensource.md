# 开源工程规范

## 发布基础设施

- 使用明确的开源许可证；发布前检查模型、SDK、容器和插件依赖的许可证兼容性。
- README 提供定位、架构概览、快速开始、配置、安全限制、示例和故障排查。
- CONTRIBUTING 规定开发环境、分支、提交、测试、文档和 ADR 规则。
- SECURITY 说明漏洞报告方式、支持版本和敏感信息处理；不把密钥提交到仓库。
- CHANGELOG 记录用户可见行为、迁移和破坏性变更；版本遵循语义化版本或明确的预发布策略。
- GitHub Actions 运行格式、类型、单元/集成/E2E、安全扫描、依赖审查和文档链接检查。
- 提供 Dockerfile、Docker Compose、示例配置、健康检查和最小权限运行用户。
- 提供 Issue/PR 模板、CODEOWNERS（有维护者后启用）和兼容性矩阵。

## 贡献者体验

新贡献者先读 Agent.md 和目标任务；新增模块必须说明端口、适配器、测试和文档影响。公开接口、状态模型、权限边界和部署方式变化必须有 ADR。贡献者不能通过修改提示词绕过程序安全策略。

## 用户体验

默认配置应能在本地安全运行；危险能力必须显式开启。首次启动给出缺失配置和权限说明；任务状态、审批、错误和恢复动作可查询。所有外部渠道都支持停用，单个适配器故障不应阻塞核心任务。

## 发布门槛

发布前必须完成核心 E2E、安全回归、依赖许可证检查、镜像扫描、升级/回滚演练、文档链接检查和已知限制记录。发布包不能依赖开发机私有路径或未声明的外部服务。
